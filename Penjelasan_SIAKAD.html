Sistem Informasi Akademik

Penjelasan isi proyek, langkah menjalankannya, dan cara setiap bagian kode bekerja.

SIAKAD adalah aplikasi web untuk mengelola kegiatan akademik satu kampus. Ada tiga peran pengguna, dan setiap peran melihat menu yang berbeda setelah login.

PeranYang bisa dilakukan
AdminMengelola data mahasiswa, dosen, program studi, mata kuliah, dan tahun akademik. Membuka jadwal kelas (sistem menolak jadwal yang bentrok), mengaktifkan semester, serta membuka/menutup periode KRS. Akun login dosen dan mahasiswa dibuat otomatis.
DosenMelihat kelas yang diampu dan menginput nilai Tugas, UTS, dan UAS. Nilai akhir dan huruf dihitung otomatis. Dosen wali juga bisa memantau IPK dan KRS mahasiswa bimbingannya.
MahasiswaMengisi KRS dengan pengecekan otomatis (jadwal bentrok, kuota, batas SKS menurut IPS), melihat jadwal mingguan, KHS per semester, dan transkrip beserta IPK. KRS, KHS, dan transkrip bisa dicetak.

Tampilan

Antarmuka meniru aplikasi Settings di iPad: sidebar berisi daftar menu dengan ikon berwarna, konten berupa list putih di atas latar abu-abu, dan judul besar di setiap halaman. Sudut elemen sengaja dibuat kecil (3–6 piksel) agar terlihat rapi dan tidak berkesan "membulat semua".

Folder system/ CodeIgniter sudah disertakan, jadi aplikasi bisa langsung dijalankan tanpa Composer.

Membangun dari Nol

Kalau ingin mengulang pembuatan proyek ini langkah demi langkah (misalnya untuk tugas atau laporan), ini urutannya. Setiap perintah make: menghasilkan kerangka file, lalu isinya ditulis sesuai file di proyek.

  1. Buat proyek baru (butuh Composer): 
    composer create-project codeigniter4/appstarter siakad
cd siakad
copy env .env          # Linux/Mac: cp env .env
  2. Atur .env (database, baseURL), lalu atur app/Config/App.php: $indexPage = '', $appTimezone = 'Asia/Jakarta', $defaultLocale = 'id'.
  3. Buat migration dan seeder: 
    php spark make:migration CreateSiakadTables
php spark make:seeder DatabaseSeeder
  4. Buat model untuk setiap tabel: 
    php spark make:model ProdiModel
php spark make:model DosenModel
php spark make:model MahasiswaModel
php spark make:model UserModel
php spark make:model MataKuliahModel
php spark make:model TahunAkademikModel
php spark make:model KelasModel
php spark make:model KrsModel
  5. Buat filter untuk login dan hak akses, lalu daftarkan alias-nya di app/Config/Filters.php: 
    php spark make:filter AuthFilter
php spark make:filter GuestFilter
php spark make:filter RoleFilter
  6. Buat controller, termasuk yang berada di subfolder per peran: 
    php spark make:controller Auth
php spark make:controller Dashboard
php spark make:controller Admin/Mahasiswa      # juga Dosen, Prodi, MataKuliah, Kelas, TahunAkademik
php spark make:controller Dosen/Kelas          # juga Perwalian
php spark make:controller Mahasiswa/Krs        # juga Jadwal, Khs, Transkrip
  7. Tulis rute di app/Config/Routes.php, helper di app/Helpers, library di app/Libraries, view di app/Views, serta CSS/JS di public/assets.
  8. Jalankan php spark migrate, php spark db:seed DatabaseSeeder, dan php spark serve. Untuk melihat semua rute yang terdaftar beserta filternya, gunakan php spark routes.

Contoh: mahasiswa menekan tombol Ambil di halaman KRS. Browser mengirim POST /mahasiswa/krs/ambil. Inilah jalur yang dilalui request tersebut:

→

→
Filterscsrf cek token, auth cek login, role:mahasiswa cek peran
→
ControllerAmbil data lewat Model, periksa aturan lewat Library
→
ModelQuery Builder → SQL ke MySQL
→
Redirect / ViewKembali ke halaman KRS dengan pesan sukses atau gagal

Jika salah satu filter menolak (belum login, atau peran salah), controller tidak pernah dijalankan. Pengguna langsung diarahkan ke /login atau /dashboard dengan pesan.

Pembagian tugas (MVC + library)

Model
Hanya mengurus data: kolom yang boleh diisi ($allowedFields), timestamp otomatis, dan query gabungan yang sering dipakai, misalnya KelasModel::detail() yang menggabungkan kelas dengan mata kuliah, dosen, tahun akademik, dan jumlah peserta.
Library
Aturan bisnis yang dipakai di banyak tempat. IndeksPrestasi menghitung IPS, IPK, dan batas SKS. AturanKrs berisi 7 syarat pengambilan kelas. Dengan begitu controller tetap pendek dan aturannya cukup diubah di satu tempat.
Controller
Menerima input, memvalidasi, memanggil model/library, lalu memilih view atau redirect.
View
Hanya menampilkan data. Semua output dilewatkan esc() untuk mencegah XSS.
Config/Akademik.php
Angka-angka kebijakan kampus (bobot 30/30/40, skala A–E, batas SKS). Jika kampus memakai aturan lain, cukup ubah file ini.

Kelas ≠ mata kuliah
Mata kuliah adalah isi kurikulum (Pemrograman Web, 3 SKS). Kelas adalah penawaran mata kuliah itu pada satu semester, lengkap dengan dosen, hari, jam, ruang, dan kuota. Satu mata kuliah bisa dibuka beberapa kelas (A, B).
KRS menyimpan nilai
Satu baris krs berarti "mahasiswa X mengambil kelas Y". Nilai dari dosen disimpan di baris yang sama, sehingga KHS dan transkrip cukup membaca tabel krs. nilai_huruf yang masih kosong berarti belum dinilai.
Tahun akademik aktif
Hanya satu baris yang memiliki is_active = 1. KRS hanya bisa diisi bila semester itu memiliki krs_dibuka = 1.
Kunci unik
nim, nidn, username, dan kode mata kuliah tidak boleh ganda. Pasangan (mahasiswa_id, kelas_id) pada krs juga unik.

Login & Hak Akses

  1. Login (Auth::attempt): username dicari di tabel users, lalu password dicocokkan dengan password_verify(). Password tidak pernah disimpan dalam bentuk asli, hanya hash dari password_hash().
  2. Batas percobaan: Throttler CodeIgniter membatasi 5 percobaan per menit untuk tiap kombinasi IP dan username, sehingga tebak-tebakan password menjadi lambat.
  3. Session: setelah berhasil, ID session diganti (mencegah session fixation) dan data penting disimpan di session('user'): id, nama, role, dosen_id, mahasiswa_id.
  4. Filter: grup rute memasang auth (harus login) dan role:admin / role:dosen / role:mahasiswa. Satu baris di Routes melindungi seluruh grup.
  5. Kepemilikan data: filter peran saja tidak cukup. Dosen A tidak boleh membuka kelas dosen B dengan mengganti angka di URL. Karena itu Dosen\Kelas::kelasMilikSaya() memeriksa kelas.dosen_id, dan mahasiswa hanya bisa membatalkan baris KRS miliknya sendiri.
  6. CSRF: filter csrf aktif global, sehingga setiap form POST wajib membawa csrf_field(). Hapus, logout, dan aksi lain sengaja memakai POST, bukan tautan GET.
// app/Config/Routes.php (potongan)
$routes->group('', ['filter' => 'auth'], static function ($routes) {
    $routes->group('admin', ['filter' => 'role:admin', 'namespace' => 'App\Controllers\Admin'], ...);
    $routes->group('dosen', ['filter' => 'role:dosen', ...], ...);
    $routes->group('mahasiswa', ['filter' => 'role:mahasiswa', ...], ...);
});

Validasi

Aturan ditulis sebagai array lalu diperiksa dengan $this->validate(). Jika gagal, redirect()->back()->withInput() mengembalikan isian lama, dan pesan error muncul di bawah field yang salah, dalam Bahasa Indonesia dari app/Language/id/Validation.php.

'nim' => ['label' => 'NIM', 'rules' => "required|alpha_numeric|max_length[20]
            |is_unique[mahasiswa.nim,id,{$id}]|is_unique[users.username,id,{$userId}]"],

Pada is_unique[mahasiswa.nim,id,5], bagian id,5 berarti "abaikan baris dengan id 5", supaya saat mengedit, NIM milik data itu sendiri tidak dianggap ganda.

Mahasiswa dan akunnya disimpan dalam satu transaksi

$db->transStart();
$id = $this->mahasiswa->insert($data);
(new UserModel())->buatAkun($data['nim'], $data['nama'], 'mahasiswa', mahasiswaId: $id);
$db->transComplete();   // jika salah satu gagal, keduanya dibatalkan

Mencegah jadwal bentrok

Saat admin menyimpan kelas, KelasModel::cariBentrok() mencari kelas lain di semester yang sama, pada hari yang sama, dengan jam yang beririsan, dan memakai dosen atau ruang yang sama. Dua rentang waktu dianggap beririsan bila mulaiA < selesaiB dan mulaiB < selesaiA.

->where('kelas.hari', $data['hari'])
->where('kelas.jam_mulai <', $data['jam_selesai'])
->where('kelas.jam_selesai >', $data['jam_mulai'])
->groupStart()->where('kelas.dosen_id', $data['dosen_id'])->orWhere('kelas.ruang', $data['ruang'])->groupEnd()

Penghapusan yang aman

Sebelum menghapus, controller memeriksa ketergantungan data. Dosen yang masih mengajar, mata kuliah yang sudah punya kelas, kelas yang sudah punya peserta, dan tahun akademik yang aktif tidak bisa dihapus. Pengguna mendapat pesan yang jelas, bukan error database.

Modul Dosen

  1. Halaman Kelas & Nilai menampilkan kelas dosen per semester, dengan semester aktif di bagian paling atas.
  2. Halaman nilai berisi tabel peserta dengan tiga kolom input. Nama input berbentuk array: nilai[krs_id][tugas], sehingga satu tombol Simpan mengirim nilai semua peserta sekaligus.
  3. Saat dosen mengetik, app.js langsung menghitung nilai akhir dan huruf memakai bobot dan skala yang sama dari server (dikirim lewat atribut data-bobot dan data-skala). Input yang bukan angka 0–100 ditandai merah.
  4. Server tetap menghitung ulang dan tidak mempercayai hasil dari browser. simpanNilai() hanya menerima krs_id yang memang milik kelas itu, menolak angka di luar 0–100, lalu menyimpan nilai akhir dan huruf menggunakan helper hitung_nilai_akhir() dan nilai_huruf().
  5. Perwalian: dosen melihat mahasiswa bimbingannya beserta IPK, SKS lulus, dan SKS KRS semester ini. Mahasiswa yang belum mengisi KRS diberi tanda.

Rumus IP & Batas SKS

Semua perhitungan berada di App\Libraries\IndeksPrestasi.

IP  = Σ (SKS × bobot huruf) ÷ Σ SKS

IPS = IP dari mata kuliah satu semester
IPK = IP dari seluruh mata kuliah; bila satu mata kuliah diambil lebih
      dari sekali, hanya nilai terbaik yang dihitung (nilaiTerbaik())
Contoh: Algoritma (4 SKS, A = 4,0), Matematika Diskrit (3 SKS, B = 3,0), Kalkulus (3 SKS, AB = 3,5).
Mutu = 4×4,0 + 3×3,0 + 3×3,5 = 16 + 9 + 10,5 = 35,5. SKS = 10. IPS = 35,5 ÷ 10 = 3,55.

Mata kuliah yang belum dinilai tidak ikut dihitung. Huruf E tetap masuk perhitungan IP, tetapi SKS-nya tidak dihitung sebagai SKS lulus.

Troubleshooting

"The framework needs the following extension(s)… intl"
Ekstensi intl belum aktif. Aktifkan extension=intl di php.ini, lalu restart.
"Unable to connect to the database"
